## Significado dos números

`tools/analyze_cfg.py:static_coverage` contabiliza palavras possuídas por ao menos uma entrada identificada; uma palavra com qualquer proprietário traduzido já conta como traduzida, inclusive se existir outro proprietário. `tools/codegen.py:write_coverage_report` calcula translated_share como translated_words / owned_words. Assim 486898/486898 = 1,0 exclui 1160 não atribuídas e 30 de padding: não é percentual sobre todo o trecho executável e não demonstra que o código gerado esteja semanticamente correto, compile ou cubra todos os fluxos. 0 interpreter_words e 0 funções interpretadas são informações estáticas desse ensaio, não provam ausência de todos os caminhos de interpretação no runtime final.

O classificador marca uma palavra sem proprietário e de valor não zero como unowned-executable; se zero, padding. Pode ser código não alcançado pela análise, instrução não identificada ou dados dentro do trecho, sem prova de execução. `owner-conflict` significa múltiplas entradas podem alcançar mesma palavra; não demonstra defeito. `interior-entry` tem precedência na classificação sobre conflito. A lista `ownership_conflicts`, por sua vez, contém todas as palavras com múltiplos proprietários, inclusive as de entrada interior; portanto não é necessariamente igual ao campo owner_conflict_words.

A análise insere aresta unresolved-indirect para `jr` cujo registrador não é RA, ou `jalr`: 780 computed-call e 90 computed-jump no relatório CFG privado. Estas arestas representam alvo calculado não resolvido estaticamente, não 870 falhas reais, nem 870 alvos únicos, e podem fazer parte de chamadas legítimas através de ponteiros. Os 870 pontos estão atribuídos no CFG: 806 owned e 64 owner-conflict. Há 4148 candidatos a tabela: na implementação é cada palavra de seção de dados não executável com valor igual a um endereço no trecho analisado, sem provar ser tabela de saltos. Os 4148 apontam a palavras atribuídas nesse relatório; ainda não se demonstra associação a qualquer uma das arestas indiretas.
